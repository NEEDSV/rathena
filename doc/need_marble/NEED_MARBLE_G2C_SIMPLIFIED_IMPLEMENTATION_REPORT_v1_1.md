### 1.3 구현 중 고친 두 가지 (실측으로 발견)

1. **적립 시점을 대화창 앞으로 옮김.** 처음에는 `F_BG_Badge` 끝(기존 보상 뒤)에 두었다. 그런데 이 함수는 `close2` 에서 플레이어 응답을 기다린다. 닫기 버튼도 활동(idletime)으로 갱신되므로, 끝에 두면 AFK 판정이 사실상 동작하지 않는다. 보상이 시작되는 시점, 즉 대화창이 뜨기 전에 판정·적립하도록 옮겼다.
2. **자동 지급 사전 루프.** 기존 자동 지급 루프는 플레이어마다 대화창에서 멈춘다. M1 실측에서 AFK 한 명 뒤의 팀원은 루프가 끝나지 않아 아무것도 받지 못했다(4.2). 마블 적립은 루프 앞에서 맵 위 멤버 전원에게 먼저 하도록 했다. 보상 루프의 `F_BG_Badge` 에서 다시 호출되면 ALREADY 가 된다.

## 4. 남은 한계와 운영자 결정 사항

### 4.1 짧은 끊김 후 재접속은 인정되지 않는다 (기존 BG 동작)
- rAthena BG 는 로그아웃 시 팀에서 빼고(`bg_team_leave`), 재접속하면 저장 위치로 보낸다. 랜덤 매치 애드온에는 재합류 기능이 없다.
- 그래서 기존 BG 보상도 마블도 받지 못한다. 요청서의 "가급적 인정"을 하려면 BG 재합류를 만들어야 하므로 이번 범위 밖으로 두었다.

### 4.2 기존 자동 지급 루프 결함 — 별도 수정 권장 (마블은 보호됨)
- `F_BG_RM_AutoRewardBadge` 는 플레이어마다 `F_BG_Badge` 의 `close2` 에서 응답을 기다린다.
- M1 실측 경과:
  - AFK 가 응답하지 않으니 90초가 지나도 루프가 끝나지 않았다.
  - 그 뒤 스크립트가 종료됐다(NPC 보안 타임아웃 60초로 추정).
  - AFK 뒤 순서의 팀원은 **기존 BG 보상을 못 받았다**.
  - 자동 지급을 한 번 더 호출하고서야 지급됐다.
- 마블 점수는 사전 루프로 영향이 없다. 기존 보상 흐름을 바꾸는 수정이라 이번에는 고치지 않았다. 자동 경로에서 대화창 없이 지급하는 별도 작업을 권장한다.

### 4.3 수동(비랜덤) BG 는 마블 대상이 아니다
- 운영자가 리더 등록으로 여는 수동 경기는 경기 토큰이 없다. 훅도 `$@BG_RM_CYCLE_ACTIVE` 조건이라 적립하지 않는다.
- 수동 경기도 넣어야 하면 BG 팀 id 같은 다른 경기 키가 필요하다. 운영자 결정이 필요하다.

### 4.4 AFK 판정 방식
- 기존 BG 에는 믿을 만한 AFK·참여 신호가 없어서 최소 규칙만 넣었다.
- 활동으로 보는 것: 이동, 스킬, 아이템, 공격, NPC 대화(`idletime_option 0x7C1F`). 채팅·명령어는 활동이 아니다.
- 운영값: 측정 30초마다, "최근 60초 안에 행동"이면 활동 → 경기 중 한 번이라도 활동이면 인정.
- 오탐 가능성:
  - 경기 내내 채팅만 한 경우는 AFK 로 본다.
  - 측정값이 하나도 없는 경우(30초 미만 체류)는 인정한다.
  - NPC 경로는 클릭 자체가 활동이라, 끝나고 돌아와 직접 수령한 사람은 인정된다.
