## 1. 변경 방법과 적용 시점

```sql
-- 예: 교환 비용을 다음 논리 일자부터 60점으로 (실제 실행은 운영자 승인 후, 운영 DB 기준)
INSERT INTO need_marble_policy (policy_key, effective_day, value, changed_by, changed_at)
VALUES (10, 20261105, 60, '<운영자>', NOW());
```

| 규칙 | 내용 |
|---|---|
| 적용 시점 | `effective_day`(YYYYMMDD, 04:00 KST 기준 논리 일자)가 되는 날부터. map-server 는 논리 일자가 바뀌면 다시 읽는다 → **다음 04:00 KST 이후 첫 마블 동작부터** 적용 |
| 소급 | 없음. 원장 행에는 그때 쓴 값(인정 점수, CP 금액)이 남는다 |
| 같은 날 변경 | 권장하지 않음(하루 한 번만 다시 읽음). 오늘 날짜로 넣어도 다음 날부터 반영된다 |
| 값 검증 | 확률 합 10000, 워프 목적지 유효, 비용·구간 양수, **CP 적용 키 5 = 0** 등. 하나라도 어기면 **마블 전체가 비활성**되고 map-server 오류 로그가 남는다 → 넣기 전에 같은 값을 격리 DB 에서 먼저 확인 |
| 되돌리기 | 같은 키에 더 늦은 `effective_day` 로 원래 값을 넣는다(행 삭제보다 이력이 남음) |

## 3. 경제 규모 (v1.0 기본값, 오프라인 계산)

| 항목 | 값 | 근거 |
|---|---|---|
| 도착 칸 기대값 | 1,067.4 CP/롤(던전 안전) ~ 1,085.6(도전) | 단위 시험 G1-4, 균등 착지 가정 |
| 33걸음 보너스 기대값 | 10,000 × 3.5/33 ≈ 1,060.6 CP/롤 | L1 정의(워프 영향 없음) |
| 합계 | 약 2,128 ~ 2,146 CP/롤 | |
| 하루 최대 | 주사위 4개 ≈ 8,500 ~ 8,600 CP/계정 | 활동 점수 200 / 50 |
| 14일 최대 | 약 120,000 CP/계정 | 매일 상한·전량 사용 가정, 개인 보장액 아님 |

워프 목적지 7→13, 22→28 로 착지 분포를 반영하면(오프라인 마르코프 계산, 세션 스크래치 `board_ev_v10.py`) 도착 칸 기대값은 1,070.0(안전) ~ 1,089.8(도전) CP/롤로 균등 가정과 거의 같다. 33걸음 보너스는 L1 이라 워프와 무관하게 1,060.4 CP/롤이다. 참고로 v1.2 현행 완주 정의(L2: START 도착 + 33걸음)였다면 이 목적지에서 602.6 CP/롤로 크게 줄었을 것이다 — 요청서가 L1 을 정했으므로 이번 구현은 L1 이다.
