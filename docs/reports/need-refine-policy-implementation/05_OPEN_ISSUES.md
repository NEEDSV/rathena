## 2. 1·2차 권고안과 확정 정책의 충돌 (확정 정책대로 구현함)

| 항목 | 2차 보고서 판정 | 확정 정책(구현) | 기록 |
|---|---|---|---|
| 대축 천장 1천만 | GO WITH GUARDRAILS (계정 주 3) | 1천만, **계정 한도 없음**, 서버 주 100 | 계정 한도·귀속 미구현. 2차 데이터상 1계정이 천장 대축의 54.7%를 샀고, 포인트 기준 잠재 수요(392~457)가 주 100을 넘는다. 4주 관측 지표 1번으로 감시 |
| +7 200P | HOLD (필요성 미입증) | 200P + 0 | 미사용 +7이 1,287장이라 체감 효과는 작을 수 있다 |
| +9 포인트 | 2,500P + 5천만 추천(B안), 2,000P + 1억도 조건부 가능 | **2,000P + 1억(CM안)** | 2,500P안은 적용하지 않음 |
| +9 한도 | 신규 경로 **통합 계정** 월 1 | **서버 전체** 월 1 (102 + 104 합산) | 계정 한도 아님. 서버 월 1이라 첫 구매자가 그 달을 가져간다 |
| 대축 → +9 | HOLD (12·15 모두) | **15개 도입** | 자동 인하 없음. 4주 관측 후 별도 승인 |
| 대축 → +7 | HOLD (효용 낮음) | **1개 도입** | 대축이 공급 과잉인 +7로 빠지는 경로. 사용량은 npclog로 관측 가능 |

## 3. 기존 구조의 한계 (이번에 바꾸지 않음)

| # | 내용 | 영향 |
|---|---|---|
| L1 | DB 재고 차감과 아이템 지급 사이에 크래시가 나면 "재고 감소 + 미지급" 가능(중복 지급은 아님) | 복구는 npclog와 재고 대조로(03 §3). DB와 인벤토리 간 완전 원자성은 없다 |
| L2 | 교환 규칙 4쪽 "천장으로 확정 교환한 아이템은 계정 귀속입니다"는 공용 희귀(Bound 0)에는 맞지 않는 기존 문구 | 103·104도 Bound 0(보장권 자체가 NoTrade). 문구 정정은 별도 승인 |
| L3 | `need_lucky_ceiling.txt` 머리말의 "시즌 44종" 설명은 오래된 내용(현재 128종) | 주석에 "최초 등록 당시 기준"이라고 표시만 함 |
| L4 | 로컬 행알 출시 도구 정책의 `pid.public`가 [100,101,102] | 103·104 추가 권장(04 §4). 도구는 최대 PID 기준으로 다음 번호를 정하므로 당장 충돌은 없다 |
| L5 | 선물포장사로 보장권 → 거래 가능 상품권 변환 가능(기존 기능, 변경 금지 대상) | 신규 교환으로 받은 보장권도 포장 가능. 새 역교환 고리는 없음(포장 결과는 상품권 → 보장권 방향만) |

## 5. 기타 확인 필요

- 운영 맵서버 구성: 천장 NPC가 맵서버 1대에서만 동작하는지. 이번 변경으로 여러 대에서도 DB 재고 아래로는 팔 수 없게 됐지만, 메모리 표시값은 서버마다 다를 수 있다.
- 위키·가이드·NeedAsk·공지의 기존 가격 서술(대축 1억, +7 1,000P, +9 5,000P + 5억) 갱신. 이번 범위 밖이다.
- 이번 시험에 쓴 격리 MariaDB(포트 3399, scratchpad 데이터 폴더)는 작업 종료 시 중지한다.
