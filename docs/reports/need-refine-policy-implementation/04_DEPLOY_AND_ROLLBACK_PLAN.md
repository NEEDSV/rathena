# 04. 적용·검증·원복 절차 (실행하지 않음)

> 이 문서의 어떤 단계도 실행하지 않았다. 운영 반영과 커밋·병합은 운영자의 별도 지시가 필요하다.

## 1. DB 스키마 변경

**없음.** 기존 `need_lucky_ceiling_stock` 테이블(PK `product_id`)을 그대로 쓴다.
- 신규 PID 103은 무제한이라 행을 만들지 않는다. 104는 102 행을 공유한다.
- DDL·마이그레이션·백필이 필요 없다.

## 2. 적용 전 인게임 QA (테스트 서버, 운영 DB 금지)

테스트 계정·테스트 DB에서 `02_TEST_REPORT.md`의 NOT RUN 항목을 아래 순서로 실행한다.

1. **천장 메뉴:** "공용 희귀"에 대축(1천만)·봉인된인장 카드·+9 제련 교환권(2,000P + 1억)·"대축 1개 → +7 보장권"·"대축 15개 → +9 보장권"이 보이는지, KO/EN 문구가 맞는지
2. **대축 천장:** 200P + 1천만 성공 / 제니 9,999,999 실패 / 199P 실패 → 실패 시 포인트·제니·재고 무변화
3. **+7 바터:** 무기·방어구 각각 200P 성공(제니 무변화) / 199P 실패
4. **대축 → +7:** 대축 0개 실패, 1개 성공(대축 0), 2개 성공(대축 1), 선택 화면에서 취소 시 무차감, 받은 보장권이 거래 불가(NoTrade)인지
5. **대축 → +9:** 대축 14개 실패 / 15개 성공(0 남음) / 16개 성공(1 남음)
6. **+9 포인트:** 2,000P + 1억 성공 / 1,999P 실패 / 99,999,999z 실패
7. **공유 월 재고:** (월 재고 1로 초기화 → `@ceiladmin` "기본 재고로 즉시 초기화")
   - 포인트 구매 → 대축 메뉴에 "(품절)" 표시와 구매 거부
   - 재초기화 후 대축 구매 → 포인트 쪽 품절
   - 무기와 방어구를 교차로 시도, 같은 계정의 다른 캐릭터로 시도 → 합계 1
8. **동시성:** 두 계정이 동시에 최종 확인 → 1건만 성공, 다른 쪽은 "방금 다른 유저가 마지막 수량을 가져갔습니다"이고 차감 없음
9. **장애:** 테스트 DB를 잠시 중지한 상태에서 재고 상품 구매 → "재고 시스템 점검 중", 차감 없음
10. **재시작:** 월 재고 0 상태에서 맵서버 재시작 → 0 유지
11. **회귀:** 시즌 천장 1개 구매(재고·로그 정상), 전장 증표 바터, 환생 상점, 추석 교환, 홀그렌 제련권 사용(+7/+9 보장권 적용), 선물포장사 포장
12. **로그:** npclog에 구매 1건당 1행, `egg=6635x1/15`, `skey=102`

## 3. 운영 적용 절차 (승인 후)

1. 작업 브랜치를 커밋하고 검토한다(운영자). `need-server` 병합은 운영자가 결정한다.
2. 적용 대상 파일 2개: `npc/NEED/need_lucky_ceiling.txt`, `npc/NEED/need_barters.yml`
   - 바이너리 재빌드는 필요 없다.
   - 클라이언트 패치도 필요 없다(신규 아이템 없음, 기존 보장권 ID 사용).
3. 적용 시점의 운영 DB 재고 상태를 기록한다(실행은 운영자): `SELECT * FROM need_lucky_ceiling_stock WHERE product_id IN (100,101,102);`
   - 같은 시점에 +7 보장권·상품권 보유 스냅숏(03 §2.2)과 행운 포인트 분포를 **기준선**으로 남긴다. +7 200P 교환량은 이 기준선 대비 주간 변화로만 대리 관측한다(B2 수용).
4. 반영: 맵서버 재시작 또는 `@reloadscript`(천장 NPC) + `@reloadnpc`/재시작(바터).
   - 바터 0제니는 키를 명시해 두었으므로 재적재로 반영된다.
   - 천장 재고는 OnInit의 SQL 재적재로 이어진다. 재고는 리셋되지 않는다(같은 주기라면 기존 값 유지 — T4).
5. 반영 직후 확인: `@ceiladmin`으로 PID 100/102/103/104 가격·재고·"재고 공유 : PID 102" 표시를 보고, npclog에 `SQL LOAD OK`가 있고 `share config` 오류가 없는지 본다.
6. 공지: 가격(대축 1천만, +7 200P, +9 2,000P + 1억), 신규 교환(대축 1 → +7, 대축 15 → +9), **+9는 포인트·대축 교환 합산 서버 월 1개**
